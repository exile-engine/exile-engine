# Bounded PoE1 Spark reference comparison

The supported fixture suite compares **selected-skill hit DPS and CombinedDPS** for normal Spark, part 1 (`1 Hit`). It counts one lightning hit per self-cast; hits per second equal casts per second. Disabled critical mode uses the noncritical mean. Explicit average-critical mode mixes noncritical and critical means by critical chance. CombinedDPS equals hit DPS because this slice excludes ailment damage, damage over time and other damage sources. Explicit externally configured shock changes damage taken by those same hits; it does not add a damage source. Projectiles, duration, return paths, repeat collisions and the skill group's Full DPS count do not multiply this metric.

This is an **executed comparison with a pinned PoB development oracle**. A separate PoB checkout and its LuaJIT runtime ran the unmodified official headless wrapper outside this repository. Only versioned JSON results entered Exile Engine. The same XML fixture bytes passed through PoB's XML/item/skill/config loaders and through the adapter. For the ten configured-shock cases, PoB executed the shocked XML and a separately recorded unshocked variant; host-defined uptime is compared by weighting those observed endpoints, rather than claiming native PoB uptime behavior. The independent JavaScript arithmetic in `tests/pob-reference.test.mjs` additionally follows the reviewed branches below. All sixty-two supported fixtures pass within the stated tolerance; this establishes this fixture set, without claiming complete PoB parity.

## Versions and source authority

The reference is [Path of Building Community commit `3dbca4463c0a59079d9f7f032d8240cf868e09da`](https://github.com/PathOfBuildingCommunity/PathOfBuilding/tree/3dbca4463c0a59079d9f7f032d8240cf868e09da). Engine rules identify themselves as `poe1-selected-spark-v8`, implemented as changes on repository base `94fdb5d633de9ec6b01d8f19bd06392488160ca6`. The worktree changes are part of the result, rather than a claim that the base commit already contained them. `tests/fixtures/pob-reference.json` records both revisions, SHA-256 fingerprints of the changed calculation/adapter sources and XML fixtures, reference Git blob IDs, runtime identity, the exact game/build/snapshot identity, assumptions and numeric tolerance. `tests/fixtures/pob-oracle-output.json` retains the observed PoB output and modifier breakdown. `tests/fixtures/pob-oracle-probes.json` separately retains an executed fractional item-text probe that the bounded adapter rejects.

The engine loads the committed PoE1 client snapshot for build `26474023`, snapshot `cfbf5330f9d85f67070aa163bfd7b1e5d1eb6dc4a045bccfd408708963b052c2`. The independent pinned-source coefficient calculation resolves level 20 Spark to the same 104–1983 base lightning damage. The pinned reference and the installed game build are separate identities: matching this skill's records does not establish that all their data is identical. The engine's base damage authority remains the client snapshot.

Added damage effectiveness also comes from that client snapshot. `GrantedEffectStatSetsPerLevel.DamageEffectiveness` is 9000 in the checked Spark rows, normalized as `1 + raw / 10000 = 1.9`. It is a multiplier, so 10–20 added lightning supplies 19–38 effective added lightning. The record identifies the exact table keys and row indices at levels 1, 20 and 40; tests compare the normalized dataset values to those source fields. The pinned PoB export and executed skill both independently give 1.9. The normalizer fails on missing or invalid facts, rather than inferring effectiveness from a skill name or substituting 1.

Controlled Destruction is one of the two supported support gems: normal variant, gem levels 1–20, quality 0. Client `GrantedEffects:5539` joins statset 5547 and the exact damage/critical stat IDs. Its per-level spell-damage modifier is 25% more at level 1 and 39% more at level 20; all twenty values are checked against client rows. Its constant critical chance modifier is 80% less, and its source cost multiplier is 140%. Eligibility is checked against normal Spark's actual `Damage` skill type. No caller-provided multiplier or expression supplies these rules.

Faster Casting is the second reviewed support, also normal levels 1–20 and quality 0. Its exact effect `SupportFasterCasting` is client `GrantedEffects:1104`, joined to statset 1112. Its only damage/timing stat is `base_cast_speed_+%` (`Stats:218`), with 20% increased cast speed at level 1 through 39% at level 20. It allows `Spell` and excludes `Instant`/`FixedCastTime`; normal Spark passes those actual client type checks. Its 110% cost fact yields a 1.1 multiplier. All twenty speed/cost values are checked against exact client rows.

Spark's base critical chance comes from the same client level row: `SpellCritChance = 600`, divided by 100 to give 6%. The base player critical multiplier is a distinct pinned rule, 150%, sourced from PoB `Data/Misc.lua:89` and its use in `CalcSetup.lua:615`. It is explicitly identified as an external rule source; no client `GameConstants` row is invented for it. The three supported critical modifier IDs resolve against exact snapshot `Stats` rows 556, 558 and 95.

Resistance inputs also keep exact client vocabulary. Penetration resolves `base_reduce_enemy_lightning_resistance_%` from snapshot `Stats:597`; exposure resolves `lightning_exposure_on_hit_magnitude` from `Stats:16084`. Exposure magnitudes are authored as negative values: the verified `Mods:28533` row `LightningExposureEffectOnHitEldritchImplicit1` contains -11 for that exact stat. The 75% default maximum, 90% hard maximum and -200% resistance floor are separate pinned PoB rule constants with an external source identity; the engine does not invent client rows for those constants.

Configured shock magnitude is scenario data, rather than an item modifier or an increased-shock-effect value. The matching client vocabulary `base_damage_taken_+%_from_shock` resolves to exact `Stats:16700`; the external pinned rule source separately supplies how configured shock changes damage taken. `shock_effect_+%` is a different game stat that scales shock generation and is outside this slice. No item-line mapping to PoB's internal `ShockVal` or `DamageTaken` names is invented.

Normal Conductivity is a single already-active scenario curse, not another selected damage skill. Client effect `Conductivity` (`GrantedEffects:2430`) joins statset 2440 and normal game gem `Metadata/Items/Gems/SkillGemConductivity`. Its exact `base_lightning_damage_resistance_%` stat (`Stats:150`) ranges from -17 at level 1 to -36 at level 20. Its separate constant `chance_to_be_shocked_%` (`Stats:535`) is 25. The effect modifier is `curse_effect_+%` (`Stats:1393`). All twenty resistance/duration/radius rows are checked against the same client snapshot; ordinary quality is fixed at 0. Duration, radius and the shock-chance side stat are retained as facts without simulating application or generating shock.

## Fixtures and assumptions

`tests/fixtures/pob/` contains synthetic plain XML with explicit Build `targetVersion="3_0"`. Each successful fixture selects one enabled normal Spark gem at level 20, or level 1 for the named low-level case, quality 0, part 1, with no passives. Conductivity fixtures additionally contain one unselected normal curse in group 2; other active skills remain unsupported. The named support fixtures add normal Controlled Destruction, normal Faster Casting, or both unique supports to the same selected socket group. Their order remains explicit in source identities. Equipped item text contains only explicitly supported damage, cast-speed and critical lines and spell-specific flat added lightning ranges, and no implicit modifiers. The enemy is explicitly `None` for boss selection and has the listed lightning resistance. The original sixteen noncritical fixtures use literal `Never deal Critical Strikes`; the ten `crit-` fixtures use literal `Cannot inflict Elemental Ailments`, which selects explicit average-critical mode with excluded ailments. Nine new resistance fixtures use the noncritical assumption, and `lightning-resistance-combined` uses average critical mode. Exposure and penetration apply only in the named resistance fixtures, the combined shock/support/curse fixtures, and the Conductivity cap/floor cases. The eight `shock-` fixtures and the Faster Casting/Conductivity combined fixtures add explicit externally configured shock magnitude and host-supplied uptime. There is no inferred shock application, lucky damage, conversion, other added damage type, triggered casting, repeats, or damage over time. Chance to hit is 100%; skill DPS multiplier and quantity multiplier are both 1. No mana-sustain assertion is made. The executed oracle caught the need for `targetVersion`: omission invokes PoB's legacy conversion path, so the adapter now rejects it.

The only added-damage item grammar is `Adds X to Y Lightning Damage to Spells`, with safe nonnegative integer endpoints and `X <= Y`. Each authored line retains the ordered pair `spell_minimum_added_lightning_damage`, `spell_maximum_added_lightning_damage`, its two values and item/line provenance. Multiple lines remain distinct contributions. Generic, local weapon and attack-only added damage, other elements, conditions and ambiguous range interpretations remain unsupported. Individual endpoints supplied as unrelated percentage modifiers are rejected.

The support-rounded case detects premature rounding before the more factor: rounding the increased minimum to 132 first would produce 183; retaining the fractional value until the final rounding gives 184.

The resistance stages are:

1. Select the strongest enabled exposure and independently scale/truncate any configured Conductivity. Add both resistance reductions to raw base resistance.
2. Resolve the maximum from the original raw resistance. PoB's `enemyMaxResist=true` checkbox means the default 75% maximum. False or absent means `min(max(rawResistance, 75), 90)`; this profile does not accept an arbitrary numeric maximum.
3. Clamp the exposed resistance to that maximum and the -200% floor.
4. Subtract total penetration. There is no second floor after penetration.
5. Apply `1 - effectiveResistance / 100` to both noncritical and critical damage. Probability weighting and cast/hit counts stay the same.

## Scope limits and next comparisons

The suite is deliberately small. Executed headless endpoint comparisons and explicit host weighting cover these sixty-two supported synthetic fixtures and their stated assumptions. GUI behavior, arbitrary builds, tree allocation, other items, further support gems, support quality effects, conditional mechanics, lucky/special critical rules, generated ailments and other skills remain outside the evidence. Missing/unsupported fixtures test the adapter's refusal behavior, without requiring PoB to reject mechanics it implements. The isolated-hit API's supported modifier vocabulary is unchanged; added-damage, support, critical, resistance-pipeline, Conductivity and configured-shock behavior belong to the PoE1 selected-skill API.

Prioritize explicit conditional enemy-state applicability next, with a specified state model and changing dependency sets. Review additional damage-taken interactions separately, preserving the distinction from resistance changes and configured shock. Generated ailment/application behavior needs separate rules for thresholds, duration and feedback before any uptime inference. A support that adds repeats or triggers needs its own timing and hit-count rules; Faster Casting implements only additive cast speed, and Controlled Destruction retains its unchanged timing. See `docs/roadmap.md`. Spark multi-hit collision estimates and Full DPS remain separate future metrics; this result does not justify automatically adding other skills.
