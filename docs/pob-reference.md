# Bounded PoE1 Spark reference comparison

The supported fixture suite compares **selected-skill hit DPS and CombinedDPS** for normal Spark, part 1 (`1 Hit`). It counts one noncritical lightning hit per self-cast. A hit uses the mean of the minimum and maximum damage endpoints; hits per second equal casts per second. CombinedDPS equals hit DPS because this slice includes no damage over time or other damage sources. Projectiles, duration, return paths, repeat collisions and the skill group's Full DPS count do not multiply this metric.

This is an **executed comparison with a pinned PoB development oracle**. A separate PoB checkout and its LuaJIT runtime ran the unmodified official headless wrapper outside this repository. Only versioned JSON results entered Exile Engine. The same XML fixture bytes passed through PoB's XML/item/skill/config loaders and through the adapter. The independent JavaScript arithmetic in `tests/pob-reference.test.mjs` additionally follows the reviewed branches below. All five supported fixtures pass within the stated tolerance; this establishes this fixture set, without claiming complete PoB parity.

The reference is [Path of Building Community commit `3dbca4463c0a59079d9f7f032d8240cf868e09da`](https://github.com/PathOfBuildingCommunity/PathOfBuilding/tree/3dbca4463c0a59079d9f7f032d8240cf868e09da). The worktree changes are part of the result, rather than a claim that the base commit already contained them. `tests/fixtures/pob-reference.json` records both revisions, SHA-256 fingerprints of the changed calculation/adapter sources and XML fixtures, reference Git blob IDs, runtime identity, the exact game/build/snapshot identity, assumptions and numeric tolerance. `tests/fixtures/pob-oracle-output.json` retains the observed PoB output and modifier breakdown.

The engine loads the committed PoE1 client snapshot for build `26474023`, snapshot `cfbf5330f9d85f67070aa163bfd7b1e5d1eb6dc4a045bccfd408708963b052c2`. The independent pinned-source coefficient calculation resolves level 20 Spark to the same 104–1983 base lightning damage. The pinned reference and the installed game build are separate identities: matching this skill's records does not establish that all their data is identical. The engine's base damage authority remains the client snapshot.

## Fixtures and assumptions

`tests/fixtures/pob/` contains synthetic plain XML with explicit Build `targetVersion="3_0"`. Each successful fixture selects one enabled normal Spark gem at level 20, quality 0, part 1, with no supports, passives or other skills. Equipped item text contains only explicitly supported global damage/cast-speed lines, and no implicit modifiers. The enemy is explicitly `None` for boss selection and has the listed lightning resistance. The literal noncritical custom modifier is required. There is no shock, exposure, penetration, lucky damage, conversion, flat added damage, triggered casting, repeats, or damage over time. Chance to hit is 100%; skill DPS multiplier and quantity multiplier are both 1. No mana-sustain assertion is made. The executed oracle caught the need for `targetVersion`: omission invokes PoB's legacy conversion path, so the adapter now rejects it.

The no-damage case has a supported mathematical zero, unlike missing or unsupported data. `missing-config` and `unsupported` must retain diagnostics/unresolved data and expose no selected-skill input, so they cannot be mistaken for zero-DPS successful imports.

Every numeric comparison uses `abs(actual - expected) <= 1e-9 + 1e-12 * abs(expected)`. The tests check base endpoints and mean, each exact stat ID/value and item-line source identity, additive totals, pre/post-resistance endpoints and mean, cast time, cast frequency, hit count, included damage, hit DPS and CombinedDPS. The PoB breakdown records pre-resistance integer endpoints separately from fractional effective endpoints. Explicit comparison-only mappings translate the observed PoB `Damage` flags 0/2/1024, `LightningDamage` flag 0 and `Speed` flag 16 to the five game stat IDs; every source is the equipped synthetic item. Saved PoB output fields do not provide the engine's answer: the fixtures deliberately contain a false cached CombinedDPS of 999999999, which both live calculators replace.

## External oracle reproduction

1. Check out the pinned PoB commit in a separate development directory, including `src` and `runtime`. Verify that tracked source/runtime files are unchanged. Do not place that checkout, binaries or a Lua observer inside Exile Engine.
2. Run its official `src/HeadlessWrapper.lua` from `src` using the pinned `runtime/lua51.dll`, with `runtime/lua` on the Lua module path and `runtime` on the native module path. This capture used an external Python 3.13.7 ctypes host, Lua 5.1/LuaJIT 2.1.1784580905, an empty command-line argument table and `CI=true`. The headless API supplies graphics stubs; the calculation and import modules remain unmodified. No updater or URL/build fetching runs.
3. For each successful fixture, read its exact XML bytes, invoke the wrapper's `loadBuildFromXML`, advance one additional frame, and observe `build.calcsTab.mainOutput`. Verify selected skill ID `Spark`, selected part 1, zero crit, hit chance 100 and action-speed modifier 1. Capture `LightningMinBase`, `LightningMaxBase`, `TotalMin`, `TotalMax`, `LightningHitAverage`, `AverageHit`, `AverageDamage`, `Speed`, `Time`, `TotalDPS` and `CombinedDPS`.
4. Observe applicable damage/cast totals and individual `Tabulate` entries from the selected skill's modifier list with its skill configuration. Capture the lightning `damageTypes` breakdown from the calculation environment for pre-resistance endpoints. Serialize numbers with 17 significant digits. Store plain JSON only, fingerprint it and the fixtures, then run `node --test tests/pob-reference.test.mjs` after the project build.

The capture metadata includes the external observer's SHA-256 and the pinned Lua DLL's Git blob/SHA-256. The observer is deliberately outside the repository. It only loads the fixtures and reads PoB's outputs; no damage formulas are supplied to the oracle. The checked-in tests do not need a Lua installation, network access or a PoB process.

## Scope limits and next comparisons

The suite is deliberately small. Executed headless parity covers these five supported synthetic fixtures and their stated assumptions. GUI behavior, arbitrary builds, tree allocation, other items, support gems, conditional mechanics and other skills remain outside the evidence. Missing/unsupported fixtures test the adapter's refusal behavior, without requiring PoB to reject mechanics it implements.

Prioritize flat added lightning damage with effectiveness, then one support gem with its more/less and cast-time effects, then explicit critical chance/multiplier. Each step needs its own fixture, exact canonical stat mapping and intermediate oracle values. Resistance/exposure/penetration and conditional applicability should follow as separate configured mechanics; see `docs/roadmap.md`. Spark multi-hit collision estimates and Full DPS remain separate future metrics; this result does not justify automatically adding other skills.
