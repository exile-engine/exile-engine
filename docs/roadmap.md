# Roadmap

## Implemented foundation

- Seven portable ESM package boundaries and strict TypeScript builds.
- Source-only repository/package checks and isolated package-consumer validation.
- Versioned client build catalogs, source provenance, SD locales, item templates and passive topology.
- Normal Spark noncritical single-hit calculation and tested English/Thai item-text interpretation.
- PoB interchange contracts with an explicit unimplemented-importer status.

## Next capabilities

1. Expand item-text grammar and reconciliation coverage with exact client fixtures, including more locales and item forms.
2. Add flat damage effectiveness, support gems and more/less modifiers with game-specific rules and independent tests.
3. Add further skill variants and mechanics, then passive/equipment integration. Keep supported mechanics explicit at each stage.
4. Implement bounded PoB XML import that resolves strong IDs directly and reconciles display text only where necessary.
5. Add further runtime smoke tests, data indexing/performance work and release automation when actual consumers justify them.

No future item is exposed as a successful runtime API before it works. Publishing remains a separate manual release decision; no npm publishing credentials or trusted publishers are configured by the scaffold.
