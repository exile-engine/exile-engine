# @exile-engine/pob

Bounded, portable PoE1 normal Spark XML adaptation. This is a deliberately small synthetic fixture profile, not a complete character importer.

`importPobXml({ format: 'pob-xml', xml, target, buildId, configurationId })` returns `complete`, diagnostics, retained unresolved fields, original bounded XML, individual increased/cast-speed contributions, grouped `addedLightningDamage` contributions, typed `supports` and, only when adaptation is complete, `selectedSkill`. Adapter revision is `poe1-spark-xml-v3`. Pass that canonical input to `calculateSelectedSkill` in `@exile-engine/poe1`. Adaptation does not prove later calculation will succeed (for example, invalid aggregate cast speed or an overflowing added-damage aggregate still fails calculation). `target` is the exact host-reviewed PoE1 game/build/snapshot binding; PoB XML does not establish a client snapshot by itself. Build and configuration IDs are explicit host identities and remain attached to the selected input.

The accepted profile has explicit `Build targetVersion="3_0"`, one level 1 Witch with no ascendancy or allocated passives; one enabled normal Spark identified by both `Spark` and `Metadata/Items/Gems/SkillGemSpark`; `mainSocketGroup="1"`, `mainActiveSkill="1"`, and explicit legacy `Skill skillPart="1"` selecting **1 Hit**. Missing targetVersion is rejected: the pinned PoB reference otherwise interprets the file as legacy 2_6 and prompts conversion. Levels 1–40 and ordinary quality 0–100 are accepted. `Build/PlayerStat` saved outputs are ignored; they never supply calculation inputs. Optional plain Notes are data only. An omitted Items section means no equipment; an included Items section uses active set 1 and at most one equipped Body Armour item.

Spark must be the first `Gem`. The same selected `Skill` group may contain exactly one optional second gem: normal **Controlled Destruction**, with `skillId="SupportControlledDestruction"`, `gemId="Metadata/Items/Gems/SupportGemControlledDestruction"`, `nameSpec="Controlled Destruction"`, integer level 1–20, quality exactly 0 and explicit `enabled="true"` or `"false"`. The XML game ID is distinct from PoB's catalog key `Metadata/Items/Gems/SkillGemSupportControlledDestruction`; the adapter validates the game ID. The canonical support has `{ id, gemLevel, quality, enabled, source }`; its source is `{ kind: 'skill', id: 'pob-gem:1:2', label: 'Controlled Destruction' }`, identifying selected group 1, gem 2. `skills` retains the active Spark separately, and `supports` retains support identity/provenance. A known disabled support remains explicit and contributes no effect. Unknown gems are rejected even when disabled; duplicates, support quality, alternate/awakened supports, other groups and additional gems are unresolved failures.

The adapter does not manufacture support modifiers. The PoE1 calculator resolves this support's client facts and records its more spell damage, less critical chance and explicit cast-time factor 1. The required `Never deal Critical Strikes` assumption keeps the less-critical-chance mechanic outside the numeric hit result while retaining its provenance. General critical calculation and additional supports remain unsupported.

Enemy configuration must explicitly supply `enemyIsBoss` string `None`, `enemyLightningResist` number between -200 and 90, and `customMods` string **exactly** `Never deal Critical Strikes`. This sole accepted custom literal declares the noncritical comparison mode; arbitrary custom modifiers are rejected. No other resistance effects are accepted, so configured resistance equals effective resistance. Values above 90 are rejected rather than silently reproducing PoB's cap. Missing configuration fails visibly.

Item text is restricted to `Rarity: RARE`, `Synthetic Spark Fixture`, `Simple Robe`, `Implicits: 0`, then explicit English modifier lines matching the following table. No affix legality or complete equipment validation is claimed. This narrow grammar is an explicit mapping, not an arbitrary display-label replacement for stat identity. Increased/reduced values map to positive/negative percentage points. Repeated occurrences retain their order, raw line label, item ID and one-based line within the original decoded Item text, including leading empty lines.

| Exact line suffix                   | Game stat ID           |
| ----------------------------------- | ---------------------- |
| increased/reduced Damage            | `damage_+%`            |
| increased/reduced Spell Damage      | `spell_damage_+%`      |
| increased/reduced Lightning Damage  | `lightning_damage_+%`  |
| increased/reduced Projectile Damage | `projectile_damage_+%` |
| increased/reduced Cast Speed        | `base_cast_speed_+%`   |

Each increased/reduced line begins with a nonnegative decimal number followed by `% `.

The sole added-damage grammar is **`Adds X to Y Lightning Damage to Spells`**, with nonnegative safe integer endpoints and `X <= Y`, matching the pinned PoB integer parser. This maps to one ordered group: `statIds: ['spell_minimum_added_lightning_damage', 'spell_maximum_added_lightning_damage']`, `values: [X, Y]`, `scope: 'global'`, and one shared item-line source. The adapter retains raw endpoints and repeated groups individually; it does not apply effectiveness or sum, reorder or flatten the pair. A zero pair remains an explicit contribution. The selected calculator applies the client Spark added-damage effectiveness and the documented hit rounding. Decimal, reversed or unsafe endpoints, generic added damage without `to Spells`, attack-only damage, other elements, local and conditional lines remain unsupported or malformed. These groups are separate from `modifiers`; a build without them has an empty imported group list and omits the optional selected-input field.

Unknown elements/attributes, multiple selections/sets, other supports, other bases/implicits, local/conditional modifiers, conversions, other added damage, allocated passives and other custom configuration remain unresolved and prevent a complete import. No successful empty-build placeholder is emitted.

The internal XML data reader has hard ceilings: 262,144 UTF-8 bytes, depth 16, 1,024 elements, 32 attributes per element and 131,072 decoded text/attribute characters. Items additionally allow 64 lines of 2,048 characters. Hosts may lower ceilings through the second argument, never raise them. DTDs, external entities, processing instructions, unknown entities, malformed XML and invalid characters are rejected. Predefined/numeric entities, comments and CDATA are handled as bounded text. No DOM, network, URL fetching, share-code decoding, decompression, Lua, executable or native dependency is used.

See `tests/fixtures/pob/` and the [executed pinned PoB comparison](../../docs/pob-reference.md) for the explicit fixture assumptions, external oracle evidence and limits.
